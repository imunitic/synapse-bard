# CLI reference

Generated by `docs/synapse-bard/generate-cli-reference.sh` from what the
binaries print for `--help`. Do not edit by hand; run the generator.

Two binaries, mirroring `synapse`/`synapse-hook`'s own relationship.
`synapse-bard` is the tooling a person or an agent runs; `synapse-bard-hook`
carries its Claude Code hooks and is registered in `settings.json` rather
than invoked directly. Neither binary links tree-sitter --
`synapse-bard` parses YAML frontmatter only.

## synapse-bard

```
usage: synapse-bard <command>

  sync                          populate _bard/graph/ from the bible's
                                source tree (always a full re-ingest)
  query <node> [--inbound]      resolved relationships (outbound by
                                default, --inbound for backlinks)
  field <node> <key>            one raw frontmatter field, verbatim
  fields <node>                 a template's own field names, so you
                                know which `field` calls are worth
                                making instead of guessing
  fields --template <name>      same, by template name directly
  search <query>                full-text over _bard/graph/
  search --field <key>:<value>  structured filter across the graph
  vault-search <query>          full-text over _bard/vault/, ranked
                                by backlink count
  vault-links <note>            every note in _bard/vault/ linking to
                                <note>
  verify                        check frontmatter/prose-body links and
                                kinds: values against the graph
  manuscript <root>             check a series manuscript and list its
                                books and chapters
  ground <root> <roster>        find where the manuscript names each
                                roster entity, into $SYNAPSE_BARD_WORK_DIR
  quote <root> <book> <chapter> <line> <text>
                                check a quote sits on a cited line
  templates [--install]         the entity kinds and their template
                                files; --install copies in the default
                                set when there is none
  mode                          generate or report, by whether the
                                bible has entity files
```

### synapse-bard sync

```
usage: synapse-bard sync
       synapse-bard sync --check

Walks the bible repo for entity files (any path with a `_`- or
`.`-prefixed folder is excluded), groups them into clusters -- the
shallowest folder in each top-level, non-excluded folder's tree that
directly contains a `.md` file -- and writes one
_bard/graph/{Cluster Title}.md per cluster, carrying a `sources:`
manifest of its member entities. Always a full re-ingest; stale
cluster nodes for folders no longer producing any entity are removed.

  --check    report whether _bard/graph/ matches what a real run
             would produce, without writing anything. Exit 0 if it
             already matches, exit 1 if it doesn't.
```

### synapse-bard query

```
usage: synapse-bard query <node> [--inbound]

  <node>       the wikilink slug, without .md (e.g. calla-starweaver)
  --inbound    backlinks -- who references <node> -- instead of outbound refs
```

### synapse-bard field

```
usage: synapse-bard field <node> <key>

  <node>    the wikilink slug, without .md (e.g. aidan-dayne)
  <key>     a root-level frontmatter key (e.g. images) -- no dotted
            nested paths
```

### synapse-bard fields

```
usage: synapse-bard fields <node>
       synapse-bard fields --template <name>

  <node>              the wikilink slug -- resolved the same way query/
                      field do, then its own template is looked up
  --template <name>   a template name directly (e.g. character_pov),
                      matching a root-level template: value verbatim --
                      for exploring a schema with no example entity
```

### synapse-bard search

```
usage: synapse-bard search <query>
       synapse-bard search --field <key>:<value>

  <query>              full-text substring, always, case-insensitive --
                       never treated as key:value even if it contains
                       a colon
  --field <key>:<value>  exact match on a root-level frontmatter field
                       across every entity (key case-sensitive, value
                       case-insensitive), e.g. --field faction:"the
                       radiant dominion"
```

### synapse-bard vault-search

```
usage: synapse-bard vault-search <query>

  <query>  full-text substring over _bard/vault/, case-insensitive,
           ranked by each
           matching note's backlink count -- most-linked first, node
           path ascending to break a tie
```

### synapse-bard vault-links

```
usage: synapse-bard vault-links <note>

  <note>  a vault-relative path, or just its filename stem (the same
          way a [[wikilink]] itself resolves) -- e.g. both
          "designs/synapse-bard/Bible-graph.md" and "Bible-graph"
          find the same note
```

### synapse-bard verify

```
usage: synapse-bard verify

Checks every entity's frontmatter refs and prose-body [[wikilinks]]
resolve to a real entity, and every kinds: value is one the
template set's kinds template (kinds_template.md, its kinds: field)
enumerates; without a kinds template the values are not checked.
Read-only -- reports findings, fixes nothing. Exit 1 if any check
found something.
```

### synapse-bard manuscript

```
usage: synapse-bard manuscript <root>

  <root>  a folder holding an index.md: a numbered list
          of paths, one per book, in series order. A book
          is a folder with its own index.md listing its
          chapter files, or a single .md file with one H1
          (the title) and one H2 per chapter.

Checks the manuscript and prints one tab-separated line
per chapter: book, chapter, file, first line, last line.
A folder or file name written as a slug (_ or - and no
space) is shown as a title: they become spaces and the
first letter is capitalized; any other name is shown as
written. Exit 1 with the reason when the manuscript does
not conform.
```

### synapse-bard ground

```
usage: synapse-bard ground <root> <roster>

  <root>    a manuscript folder, as for `manuscript`
  <roster>  a file with one entity per line, tab-separated:
            name, kind, then any number of aliases

Writes $SYNAPSE_BARD_WORK_DIR/_refs.tsv, one tab-separated
line per whole-word mention of a name or alias: term,
entity, book, chapter, file, line, SHA-256 of the line.
Sorted by term, then entity, then position. Pronouns and
other mentions without a name form are not found. Exit 1
when the variable is unset or an input is refused.
```

### synapse-bard quote

```
usage: synapse-bard quote <root> <book> <chapter> <line> <text>

Checks that <text> sits within line <line> of chapter
<chapter> of book <book>, the line being inside that
chapter. Names are the titles `manuscript` prints. Exit 0
when it does, 1 when it does not.
```

### synapse-bard templates

```
usage: synapse-bard templates
       synapse-bard templates --install

Prints one tab-separated line per template of the bible's
_templates/: its kind and the path of its file (a
{kind}_template.md). Exit 1 when it holds none.

  --install    copy the default template set the package ships
               into _templates/ and print each copy. Refused when
               _templates/ already holds a template, so nothing is
               ever overwritten.
```

### synapse-bard mode

```
usage: synapse-bard mode

Prints `generate` when the bible has no entity files yet and
`report` when it has any: the two modes of book-to-bible.
An entity file is one `sync` would ingest.
```

## synapse-bard-hook

```
usage: synapse-bard-hook <hook>

  session-start    SessionStart: inject _bard/vault/Index.md
  stop-nudge       Stop: periodic "worth writing to the vault" check-in
```
